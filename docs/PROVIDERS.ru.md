# Провайдеры, фолбэки и кастомные эндпоинты

[English](PROVIDERS.md) | [Русский](PROVIDERS.ru.md)

kvorum общается только с OpenAI-совместимыми эндпоинтами
`{base_url}/chat/completions`, поэтому облачные хосты и локальные серверы
настраиваются одинаково.

> **Примечание:** Прямые ключи от SiliconFlow или DeepSeek Native **не являются
> обязательными**. Вы можете запустить полноценный ансамбль из всех 6 моделей,
> используя **только один единый API-ключ OpenRouter** (`OPENROUTER_API_KEY`).
> Использование прямых эндпоинтов — это лишь опция для снижения латентности или
> экономии на региональных тарифах.

## Пресеты

В `examples/` поставляются два готовых пресета с идентичным составом из 6 кресел:

| Пресет | Основной | Фолбэк |
|---|---|---|
| `examples/panel.json` | SiliconFlow (+ нативный DeepSeek) | OpenRouter |
| `examples/panel.openrouter.json` | OpenRouter | SiliconFlow |

```bash
kvorum run --panel examples/panel.openrouter.json   # OpenRouter primary
kvorum run --panel examples/panel.json              # SiliconFlow primary
```

## Осторожно с двойным провайдером (primary + fallback)

Промпты ревью тяжёлые — панель из 6 кресел на большом артефакте может достигать
~1M токенов контекста — а провайдеры жёстко троттлят:

* SiliconFlow отвечает **HTTP 429** ("Request was rejected due to rate limiting…");
* OpenRouter включает ограничения **RPM/TPM**;
* медленные reasoning-модели могут превысить таймаут чтения.

С настроенным фолбэком кресло автоматически переходит на вторичного провайдера, и
запуск выживает. Отключение фолбэка (`--no-fallback`) или незаданный второй ключ
означают, что одна заминка провайдера может стоить всего кресла и уронить запуск
ниже кворума.

Идентификаторы моделей тоже дрейфуют: одна и та же модель — `zai-org/GLM-5.2` на
SiliconFlow и `z-ai/glm-5.2` на OpenRouter, и любая сторона может отозвать имя.
Дайте каждому фолбэку собственный `model` и держите запасные id в
`model_aliases` (см. [docs/CONFIGURATION.md](CONFIGURATION.md)), чтобы
переименование стоило одного лишнего запроса, а не потерянного кресла. Длинные
цепочки тоже работают: SiliconFlow → OpenRouter → Native API.

## Кастомные эндпоинты и локальные прокси

Разрешение эндпоинта (по убыванию приоритета):

1. явный `base_url` на кресле или его объекте фолбэка;
2. переменная окружения `<NAME>_BASE_URL` (`SILICONFLOW_BASE_URL`,
   `OPENROUTER_BASE_URL`, `DEEPSEEK_BASE_URL`, `OLLAMA_BASE_URL`, `OPENAI_BASE_URL`, …);
3. URL по умолчанию провайдера из блока `providers`.

Переопределение на уровне кресла:

```jsonc
{
  "seat_id": "architect",
  "seat": "GLM-5.2",
  "role": "Lead Architecture Critic",
  "provider": "siliconflow",
  "model": "glm-5.2",
  "base_url": "http://127.0.0.1:8000/v1",          // this seat hits a local vLLM
  "fallback": [
    { "provider": "openrouter", "model": "z-ai/glm-5.2",
      "base_url": "http://127.0.0.1:8080/v1" }       // fallback hits LiteLLM
  ]
}
```

Переопределение для всего окружения (без правки конфига):

```bash
export SILICONFLOW_BASE_URL=http://127.0.0.1:8000/v1
export OPENROUTER_BASE_URL=http://127.0.0.1:8080/v1
export OLLAMA_BASE_URL=http://127.0.0.1:11434/v1
```

Локальные серверы обычно не требуют ключа; задайте `OLLAMA_API_KEY=` (или
`api_key_env` провайдера) в любое значение, если ключ всё же нужен.

## Лимиты и последовательное выполнение

kvorum рассчитан на провайдеров со строгими лимитами параллелизма/RPM, поэтому
раннер работает **строго последовательно** — по одному креслу за раз, никогда
параллельно.

* **`--min-delay-s N`** — пауза между вызовами кресел (`KVORUM_MIN_DELAY_S`).
* **`--timeout` / `--fallback-timeout`** — бюджеты на один вызов.
* **`--no-fallback`** — только основные провайдеры.

Вместе с покресловыми фолбэками и fail-closed кворумом запуск деградирует
громко, а не молча теряет кресла.

## Время выполнения и тяжёлые модели

Поставляемые кресла — это 1M-контекстные reasoning-модели, выдающие длинные
цепочки рассуждений, и они намеренно работают последовательно. Живой прогон на
6 кресел через OpenRouter (пакет 153.7 KB):

| Кресло | Латентность |
|---|---|
| DeepSeek-V4-Pro | 452.7 s |
| LongCat-2.0 | 296.0 s |
| Qwen3.8-Flash | 229.5 s |
| Kimi-K3 | 195.1 s |
| MiniMax-M3 | 130.5 s |
| GLM-5.2 | 49.2 s |
| **Итого** | **1 353 s (~24 мин wall-clock)** |

Бюджет: полный прогон на 6 кресел занимает ~20–25 минут (1 300–1 500 s
латентности моделей плюс паузы `--min-delay-s`); одно кресло может превысить
**7 минут** (DeepSeek-V4-Pro — 452.7 s здесь), поэтому держите `--timeout` на
**600 s** — лимит 300 s молча обрезает такие кресла. Точечные перезапуски
(`kvorum run --seats <id>`) стоят минуты вместо полной панели. Перед любым платным
прогоном `kvorum run --preflight` проверяет пакет против лимита контекста каждого
кресла и блокирует прогон при переполнении (`--skip-overflow` отбрасывает
переполненные кресла и пересчитывает кворум); таблицу и лимиты см. в
[../README.ru.md](../README.ru.md). Полная разбивка по токенам/стоимости — в
бенчмарке Dogfooding в [../README.ru.md](../README.ru.md).
